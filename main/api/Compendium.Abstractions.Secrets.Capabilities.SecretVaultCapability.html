Enum SecretVaultCapability

Namespace
Compendium.Abstractions.Secrets.Capabilities
Assembly
Compendium.Abstractions.Secrets.dll

The optional capabilities a secret-vault adapter can declare. Consumers use the declared matrix to drive UI affordances and to select providers; adapters use EnsureSupported(SecretVaultCapability) to fail uniformly when an undeclared capability is invoked.

public enum SecretVaultCapability

Fields

EphemeralSecrets = 6

The provider supports ephemeral (auto-expiring) secrets. Not surfaced by the v1 ports; declared for capability-driven UI only.

ImmutableVersions = 0

Versions are immutable once written: the material of a revision can never change, so a revision reference is a stable rollback anchor. This is the core contract; adapters that cannot guarantee it must not declare it, and callers requiring stable history must refuse them.

LargePayload = 5

The provider accepts payloads larger than 64 KiB per version.

PathHierarchy = 3

Secrets are organized in a hierarchical path namespace that supports prefix listing.

ServerSideRotation = 7

The provider can rotate secret material server-side on a schedule. Not surfaced by the v1 ports; declared for capability-driven UI only.

Tags = 4

Secrets carry provider-side key/value tags usable as list filters.

VersionDestroy = 2

Individual revisions can be permanently destroyed (retention/cost control). Destroyed revisions read as not found.

VersionEnableDisable = 1

Individual revisions can be disabled (kill-switch for a leaked value) and re-enabled without destroying the material.
